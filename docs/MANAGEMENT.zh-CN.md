# 🛠️ Python 管理

[English](MANAGEMENT.md) · **简体中文** · [🏠 首页](../README.zh-CN.md)

管理已安装的 Python、安装源、虚拟环境和软件包；设置按类别组织，目录浏览偏好位于“安装 Python”页。

## 🕰️ 浏览与安装历史 micro

**安装 Python → 所有版本** 按 3.14、3.13 等 minor 系列整理可用包，展开后选择具体 micro。搜索、架构、预览版与发行包筛选仍然生效。可用范围由所选 PIM 源及其历史分页决定：官方来源提供的是 Windows 安装包，不是 Python 的全部源码发行版本，源中不存在的 micro 或包类型无法通过该目录安装

架构、包类型和**显示预览版本**统一在**安装 Python**页调整，即时筛选列表，并在下次打开时保留选择，包括**所有架构**及**嵌入式**、**自由线程**、**含测试套件**等具体类型。设置页不再重复提供这三项浏览偏好，**卸载前确认**仍保留在设置页

目录通过运行时 ID **和**完整版本号区分条目。安装或下载离线包前，PyDeck 请求 PIM 精确解析选中的 micro，结果不符时拒绝继续。**重新安装以修复** 请求已安装的 micro，不会静默改成更新；在线修复沿用原安装来源，版本不可取得时明确报错

同一系列、架构和发行类型的多个 micro 可能共用一个 PIM 运行时 ID，因此选择另一 micro 会**替换已有安装**，不会再创建一个同 ID 的并存条目。替换前显示当前与目标版本，并在操作锁内重新核对当前版本；确认后若发生变化，需要刷新后重新查看。替换后，解释器内的包及依赖它的虚拟环境可能需要处理

历史版本的 **下载离线包** 使用选中的 micro。从该包安装时使用经过校验的本地快照，并执行相同的替换检查，无需查询在线目录。请保留生成的完整离线包文件夹，既有的校验、归档路径、来源信任和取消规则继续生效

## ✅ 操作与核验

安装、更新、修复、卸载和取消后都会重新读取 PIM 列表。安装结果还会核对目标版本，并以隔离模式、不加载 site 初始化、带超时地启动解释器，检查 SSL、SQLite 等核心模块；这不代表所有第三方包都已验证

退出码为零不足以显示成功。缺少文件、版本不符或无法刷新列表时，结果保持未确认。更新检查不会重新安装相同版本，也不会降级

## ⚙️ PIM 配置

在 **设置 → Python 管理 → PIM 配置** 中调整默认解释器、默认平台、自动安装和是否包含非托管 Python。选择 **PIM 默认值** 会删除对应的用户覆盖项

编辑器使用标准用户配置 `%AppData%\Python\pymanager.json`，保留其他字段，保存前展示变更并创建备份，拒绝并发修改，使用原子替换。可在同一折叠项恢复这里创建的备份。存在环境变量覆盖或管理员策略时会阻止编辑，不会悄悄重写自定义配置位置

这些选项也影响 PyDeck 之外的 PIM。PyDeck 自己的子进程仍禁止隐式自动安装。暂不提供安装目录迁移，自定义源与 Shebang 规则使用独立折叠设置项

## 🔎 PATH 与别名

**设置 → Python 管理 → PATH 与别名** 对比 PIM 默认版本与 `py`、`python`、`python3`、`pymanager`，显示候选路径、被遮蔽的命令，以及进程 PATH 与保存的环境变量之间的差异

对于已知解释器和确认属于当前 PIM 的应用执行别名，会探测实际使用的解释器路径。不执行来源不明的程序，此类命令保持 **尚未验证**。Shell 函数、虚拟环境和不同 Shell 的解析规则可能与这里的可执行文件路径检查不同

诊断提供 Windows 应用执行别名设置入口，不修改 PATH。另一个 **刷新别名** 操作会请求 PIM 刷新它管理的 **全部** 解释器的注册信息和别名，不会切换由 Windows 管理的应用执行别名开关

## 🌐 代理与下载详情

**设置 → 网络与来源 → 网络** 提供使用系统设置、直连和自定义 HTTP 代理。HTTP 代理可转发 HTTPS 流量。系统模式保留继承的代理环境变量与 Windows 代理配置；更改只作用于 PyDeck 发起的操作

代理密码以当前用户的通用凭据保存在 **Windows 凭据管理器**，并关联代理地址与用户名。普通偏好设置仅保存模式、地址和用户名。捕获的 PIM 输出及错误文本会隐藏密码和 URL 中的凭据。密码留空会保留匹配的凭据，**清除已保存的密码** 用于删除凭据

对于官方 Python 包，PyDeck 按 PIM 目录信息下载并统计真实字节，校验 SHA-256 和压缩包路径后，将验证过的临时缓存交给 PIM。**安装和修复仍由 PIM 完成**，在线安装保留原来的在线源。离线安装仍只使用校验过的本地源

下载量不足 1 MB 时显示 KB，达到后显示 MB，按 1 KB = 1,024 字节换算。速度采用平滑值，已知总大小且有足够采样后才显示预计剩余时间。断线可通过核对 HTTP Range 续传，最终仍校验完整文件。缺少数据时保持未知，解压是单独的 PIM 约数进度阶段

## 🔧 检查与修复

托管版本的 **⋯ → 检查安装** 会执行基础解释器检查。**重新安装以修复** 在确认后调用 PIM 强制重装，要求相同版本仍可取得；否则应使用更新。重装可能移除解释器目录内的包或修改，不是回滚操作

## 🧩 兼容性

修改 Python 安装需要 **PIM 26.3 或更高版本**。旧版或无法识别的版本仅保留兼容的只读查询，升级后重新连接。包管理仅面向已登记的 venv，不提供全局包管理、uv/conda、环境文件删除或脚本首行编辑。

## 🧰 虚拟环境

在“虚拟环境”页面选择已安装的解释器创建环境，或导入包含 `pyvenv.cfg` 的文件夹。创建使用 `python -I -m venv`，独占创建新目录，不覆盖已有目录。失败或取消时保留未完成文件与记录，“从列表移除”只删除 PyDeck 记录

导入只读取元数据；刷新时可确认重新检查曾验证正常的环境，未验证的导入环境仍只读取元数据。检查环境或打开终端前显示实际解释器路径并确认，检查有超时限制。终端设置 `VIRTUAL_ENV` 并将 Scripts 放到 PATH 开头，不执行项目的激活脚本。检查导入环境会执行其中的解释器和正常站点初始化，请只使用可信环境；基础解释器缺失时明确提示

## 🌐 安装源

展开“设置 → 网络与来源 → 安装源”，留空使用官方来源，或主动确认信任自定义 HTTPS PIM 索引。此设置仅用于 PyDeck，不影响 pip/PyPI 或外部终端。切换来源后清空目录缓存，旧卡片无法继续安装

仅接受不含凭据、查询参数和片段的 HTTPS 地址。安装包必须提供 SHA-256，继续检查大小与归档路径，并支持代理、取消、真实速度和 ETA。安装包使用其他来源或跨站重定向时，连接前显示新来源并确认。索引解析与既有签名要求仍由 PIM 执行；校验值不能代替发行者身份认证

PIM 安装时会重新读取在线来源，临时包缓存不会冻结自定义服务器的元数据；若服务器在校验后改变安装包，PIM 可能再次下载。请信任来源维护者，安装后的版本核对可以发现不一致，但不能保证来源变化期间的整个安装事务不受影响

更新与修复从 PIM 安装元数据读取原 HTTPS 索引，不因当前浏览源变化而静默更换发行者。原来源缺失或仅为本地路径时明确报错，不自动换源；离线安装继续使用原有本地离线包入口

## 📜 Shebang 规则

PIM 26.3 及以上可展开 Shebang 规则，设置运行非 Python 程序的默认、允许或阻止行为，将模板映射到默认或指定已安装版本的 `py` / `pyw` 选择器。填写同名模板可替换规则，现有高级条目默认原样保留，只有明确移除或替换才变更。保存前预览差异，沿用备份、策略检查与外部修改检测，不通过编辑或执行用户脚本测试规则

## 🔔 PyDeck 更新

“设置 → 关于 → 检查 PyDeck 更新”通过 GitHub 查询本仓库的最新稳定版本，使用应用网络设置，排除草稿、预发布与历史 beta 标签。发现新版后，“打开发布页”用默认浏览器打开固定的 PyDeck GitHub 地址，不静默下载安装包，也不在运行中替换自身


## 🔀 任务隔离

目录刷新、应用更新检查、构建和虚拟环境包管理分别持有任务状态，无关任务运行时仍可导航、切换外观和语言、筛选列表。会相互影响的运行时修改、环境修改和空间清理继续互斥，网络与安装源的保存需等使用它们的任务结束。多个长任务可在进度区切换查看，分别取消

后台完成只更新相关页面或设置区域，保留其他设置草稿；失败和取消只释放当前任务占用的资源。已登记环境仍共用包操作与登记锁，不承诺同时修改多个环境的 pip，也无法约束任意外部终端操作

## 🛠️ 构建准备

在“构建 Python”点击“一键准备”，从官方 NuGet 来源下载独立的 Python 3.14.7 x64，并验证固定 SHA-256；复用前将文件与已验证归档逐一比对。不修改 PATH、PIM 登记或系统 Python，支持代理与取消。摘要来自官方 HTTPS 下载，不宣称验证了 NuGet 签名

准备后检测 MSVC / SDK。“安装 C++ 工具”打开微软官方页面，在 Visual Studio Installer 选择“使用 C++ 的桌面开发”、x64 编译器和 Windows SDK，再重新检查。不会静默安装 Visual Studio 或替用户接受许可；目标源码仍须与工具链兼容

## 🧹 空间管理

“设置 → 存储与日志”中的“构建空间管理”扫描源码与工具下载、独立构建工具、构建临时目录以及带归属标记的本地运行时，逐项显示路径和大小。清理前确认范围，执行前重新检查文件快照，拒绝目录链接和进行中的构建

保留历史、日志、原始导入归档、PIM 运行时和项目目录。已登记环境仍在使用的运行时不能清理。删除前更新运行时登记，防止部分删除后仍显示就绪；失败或中断可能残留文件，可重新扫描。已清理的下载缓存以后可能需要重新下载

## 🔗 使用关系

在“我的 Python”的更多菜单查看使用关系，通过运行时 ID、已保存的基础路径和当前 pyvenv.cfg 匹配已登记环境；缺失环境仍保留提示。这不是全盘项目扫描，未登记环境、运行中的程序和外部工具也可能仍在使用

PIM 卸载时若存在已知依赖，即使关闭普通卸载确认也会显示影响，操作前重新核对使用关系

## 📦 虚拟环境包管理

在虚拟环境卡片点击“包管理”，页内展开包搜索、安装、更新、卸载、pip 补装与升级、requirements 导入导出。打开前说明会运行该环境的解释器；不修改全局 Python 的包，也不提供 pip 卸载

在实际执行进程中核对 venv 身份，仅使用该环境的 pip，屏蔽可能改变安装目标的外部 pip 配置，修改前拒绝环境目录中的链接。使用 PyPI 和应用网络设置，安装第三方包可能执行其构建代码，操作前确认环境与包列表

requirements 支持每行包名、可选 extras 和版本范围，支持空行与注释；明确拒绝递归引用、命令选项、网址、本地路径和环境标记。导出记录本环境已安装的名称与版本，不是跨平台锁文件，也不保留 editable 等原始来源；外部修改环境后先刷新

包操作最长 30 分钟，可取消整个子进程组。pip 不提供事务回滚，失败或取消后可能有部分变更，因此每次操作后重新读取包列表，用 pip check 提示依赖问题。继承的系统包不作为本环境已安装包展示，基础解释器缺失时需先修复环境
