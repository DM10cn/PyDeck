# 🛠️ Python 管理

这些功能从 **0.6.0** 起提供，已发布的 0.5.1 安装包不包含这些功能

## ✅ 操作与核验

安装、更新、修复、卸载和取消后都会重新读取 PIM 列表。安装结果还会核对目标版本，并以隔离模式、不加载 site 初始化、带超时地启动解释器，检查 SSL、SQLite 等核心模块；这不代表所有第三方包都已验证

退出码为零不足以显示成功。缺少文件、版本不符或无法刷新列表时，结果保持未确认。更新检查不会重新安装相同版本，也不会降级

## ⚙️ PIM 配置

在 **设置 → Python 管理 → PIM 配置** 中调整默认解释器、默认平台、自动安装和是否包含非托管 Python。选择 **PIM 默认值** 会删除对应的用户覆盖项

编辑器使用标准用户配置 `%AppData%\Python\pymanager.json`，保留其他字段，保存前展示变更并创建备份，拒绝并发修改，使用原子替换。可在同一窗口恢复这里创建的备份。存在环境变量覆盖或管理员策略时会阻止编辑，不会悄悄重写自定义配置位置

这些选项也影响 PyDeck 之外的 PIM。PyDeck 自己的子进程仍禁止隐式自动安装。本轮不提供安装目录迁移、自定义源或 Shebang 配置编辑

## 🔎 PATH 与别名

**设置 → Python 管理 → PATH 与别名** 对比 PIM 默认版本与 `py`、`python`、`python3`、`pymanager`，显示候选路径、被遮蔽的命令，以及进程 PATH 与保存的环境变量之间的差异

对于已知解释器和确认属于当前 PIM 的应用执行别名，会探测实际使用的解释器路径。不执行来源不明的程序，此类命令保持 **尚未验证**。Shell 函数、虚拟环境和不同 Shell 的解析规则可能与这里的可执行文件路径检查不同

诊断提供 Windows 应用执行别名设置入口，不修改 PATH。另一个 **刷新别名** 操作会请求 PIM 刷新它管理的 **全部** 解释器的注册信息和别名，不会切换由 Windows 管理的应用执行别名开关

## 🌐 代理与下载详情

**设置 → Python 管理 → 网络** 提供使用系统设置、直连和自定义 HTTP 代理。HTTP 代理可转发 HTTPS 流量。系统模式保留继承的代理环境变量与 Windows 代理配置；更改只作用于 PyDeck 发起的操作

代理密码以当前用户的通用凭据保存在 **Windows 凭据管理器**，并关联代理地址与用户名。普通偏好设置仅保存模式、地址和用户名。捕获的 PIM 输出及错误文本会隐藏密码和 URL 中的凭据。密码留空会保留匹配的凭据，**清除已保存的密码** 用于删除凭据

对于官方 Python 包，PyDeck 按 PIM 目录信息下载并统计真实字节，校验 SHA-256 和压缩包路径后，将验证过的临时缓存交给 PIM。**安装和修复仍由 PIM 完成**，在线安装保留原来的在线源。离线安装仍只使用校验过的本地源

下载量不足 1 MB 时显示 KB，达到后显示 MB，按 1 KB = 1,024 字节换算。速度采用平滑值，已知总大小且有足够采样后才显示预计剩余时间。断线可通过核对 HTTP Range 续传，最终仍校验完整文件。缺少数据时保持未知，解压是单独的 PIM 约数进度阶段

## 🔧 检查与修复

托管版本的 **⋯ → 检查安装** 会执行基础解释器检查。**重新安装以修复** 在确认后调用 PIM 强制重装，要求相同版本仍可取得；否则应使用更新。重装可能移除解释器目录内的包或修改，不是回滚操作

## 🧪 兼容性与验收

修改 Python 安装需要 **PIM 26.3 或更高版本**。旧版或无法识别的版本仅保留兼容的只读查询；升级后重新连接会刷新能力检查。测试发现 PIM 25.2 和 26.3 的 `install --by-id` 均有注册阶段错误。PyDeck 改用版本选择器，在变更前确认只匹配目标 ID，结束后核验安装结果。已验证的变更基线为 26.3，不代表已验证所有后续 PIM 版本

核心检查覆盖配置冲突、敏感信息处理、命令解析、下载校验与续传、代理失败和能力变化。GUI 检查覆盖四种语言与设置窗口。破坏性的生命周期测试 **仅在一次性 Windows Sandbox 中运行**：

```powershell
.\scripts\Build.ps1 -Checks -Publish
.\scripts\Smoke-Test.ps1
.\scripts\Test-PimLifecycle.ps1
```

脚本验证官方 PIM 安装包后创建自己的无界面沙盒，使用较旧的官方 Python 包测试 PIM 25.2 → 26.3，并将逐项结果写入 `artifacts/`。结束时仅关闭它创建的沙盒。测试基线必须比在线候选版本旧，真实更新项目才能通过；可通过 `-SeedBundleDirectory` 指定平铺的离线包目录。失败与未运行项目不能计为通过

📋 当前结果与剩余验收边界见[功能状态](FEATURES.zh-CN.md)。venv、自定义源编辑和 Shebang 管理仍留待后续
